# Skill 编写约定

Skill 定义任务特有的决策、证据和完成条件。修改时同时检查 `SKILL.md`、实际分支读取的 references、行为契约和固定答案。

## 授权与继续执行

- 用户明确要求优先于 Skill 的默认流程，系统、开发者指令和宿主权限继续生效。写清哪些是可覆盖的默认值，哪些是缺少事实、能力或授权的真实阻塞。
- 从当前请求和已有上下文识别授权。已授权的可逆工作直接推进；只有无法推断且会实质改变结果的信息才提问。提问时继续不依赖答案的工作。
- 仅规划、只读、等待执行等明确边界持续有效；自动推进不能扩大到发布、部署、付费、破坏性操作或未经授权的外部发送。
- 每个阶段门只保留一个规则来源。references 引用它，避免入口允许自动推进、下游又无条件要求确认。
- 因 Skill 暂停时，给出文件链接、原句、适用原因和具体缺口；区分规则要求与 Agent 的推断。先完成可以独立准备的可审阅结果。
- 中途新增要求只更新受影响的目标、约束和待办；状态询问不取消原任务，明确停止指令则立即约束后续动作。

## 输出与工具

- 先交付结果，再给必要证据和未验证边界；按用户需要控制长度。只有比较或顺序本身有用时才使用表格或列表。
- 必需材料写在入口，分支细节通过带触发条件的链接按需读取。保留领域不变量，避免复制宿主通用规则或整份模型指南。
- 只有工作流确实需要且宿主允许时才要求委派；说明文件责任、独立完成条件和共享约束。异步工具按真实依赖排序，待完成的工具结果不能充当证据。

## 验证

- 改动行为、缺陷边界与仓库必需检查共同决定验证范围。纯文案不触发完整编译矩阵或批量出图；平台兼容性、图像质量等结论仍须对应的实际验证。
- 检查通过后，只因新修改、失败或未解决疑点扩大或重复验证。
- 阶段门变更至少覆盖已授权推进与未授权停止两种情况；可选流程覆盖不触发场景。
- 固定答案通过只说明运行器和断言可处理已知文本。真实模型质量、工具使用、工作区变更和像素质量分别需要对应证据。

这些约定采用 [GPT-6 Astra 官方指南](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra#prompting-best-practices) 的指令审计、主动完成、输出控制和适量验证建议，并保留本仓库可移植性与明确任务边界。来源核查于 2026-09-06；无需在可移植 Skill 中固定模型或推理强度。
