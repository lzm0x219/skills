Final design: adopt an exact database-backed sliding window. Assume server-assigned ingestion time in (now-1h, now] and rank equal scores by stable record ID. Delayed arrivals enter the window when accepted; queries include only committed records in a consistent snapshot. Persist records, filter the exact interval, and stream candidates through a min-heap of capacity 100. Query time is O(N log 100); selection memory is O(100) fixed-size score/ID entries, with bounded database cache, record sizes and query buffers inside the 256 MiB RAM budget. Fetch result payloads by ID with bounded buffers. Disk storage, retention and I/O remain budgeted separately.

This favors simple writes because reads are rare. Whole-minute bucket summaries cannot alone handle partially expired boundary buckets exactly. Verify against full sorting on small inputs, including a higher-scoring record expiring before a discarded lower-scoring record, ties, late events, empty windows and peak memory. These are verification plans, not executed measurements.
